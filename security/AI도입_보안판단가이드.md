# AI·에이전트 도입 보안 판단 가이드 — 망분리·폐쇄망·규정 환경

> 대상: 유지관리 사업 PM · 관리자 · 보안 담당 · 제안 담당
> 함께 보는 자료: `보안판단_슬라이드.pptx` (교육·회의용 9장), `advanced/agent_lab/mask.py` (마스킹 도구)
>
> **이 문서는 법률 자문이 아닙니다.** 개인정보·정보보호 관련 법령, 기관 보안 지침, 고객사 계약 조건은 사업마다 다릅니다. 여기 있는 판단 흐름과 질문으로 **무엇을 확인해야 하는지**를 정리하고, 최종 판단은 고객사 보안 담당과 법무 검토로 확정하세요.

## 1. 왜 따로 판단해야 하나

교육 자료의 데모와 실습은 "인터넷으로 AI API를 호출할 수 있다"고 가정합니다. 실제 유지관리 사업 현장은 다음 이유로 이 가정이 깨지는 경우가 많습니다.
- 업무망과 인터넷망이 분리되어 있다 (망분리)
- 시스템이 외부와 완전히 단절되어 있다 (폐쇄망)
- 개인정보·중요정보의 외부 전송이 계약이나 지침으로 제한된다
- 고객사가 승인하지 않은 외부 서비스 사용을 금지한다

**판단 없이 도입하면 계약 위반·보안 사고가 될 수 있고, 판단 없이 금지하면 쓸 수 있는 영역까지 놓칩니다.**

## 2. 판단 흐름: 5개 질문

| 순서 | 질문 | 답이 "모름"이면 |
|---|---|---|
| Q1 | 고객사가 외부 AI 서비스 사용을 허용하는가? (보안 지침 · 계약 · 사전 승인 절차) | 사용 전 고객사 보안 담당에게 확인 (아래 4장 질문 목록) |
| Q2 | 다루는 데이터의 등급은? 공개 / 내부 / 개인정보 포함 / 중요·기밀 | 가장 높은 등급으로 가정 |
| Q3 | 작업 환경의 망 구분은? 인터넷 가능 / 망분리 / 완전 폐쇄망 | 고객사 인프라 담당 확인 |
| Q4 | 외부로 보낼 수 있는 데이터와 조건은? (비식별 · 승인 · 망연계 절차) | 보낼 수 없다고 가정 |
| Q5 | 맡길 범위는? 분석·초안(읽기)까지 / 운영 변경(쓰기)까지 | 읽기·초안까지만 |

## 3. 적용 유형 A~E

| 유형 | 조건 | 방식 | 자율성 상한 (제안) |
|---|---|---|---|
| **A. 외부 API 직접** | Q1 허용 · 공개/내부 데이터 · 인터넷 가능 | 교육 자료 그대로. 감사 로그 · 승인 게이트 적용 | L3 |
| **B. 마스킹 후 외부 API** | Q1 허용 · 개인정보 포함 가능성 | `--mask`로 자동 마스킹 + **사람이 결과 확인** + 필요한 부분만 전송 | L3 (개인정보 다루는 조치는 L2) |
| **C. 고객사 클라우드 계약 경유** | 고객사가 이미 쓰는 클라우드 안에서 처리해야 함 | Claude는 Anthropic API 외에 주요 클라우드(Amazon Bedrock, Google Cloud Vertex AI, Microsoft Foundry)로도 제공된다. 고객사 클라우드 계약·보안 체계 안에서 쓸 수 있는지 검토 | A·B와 같음 |
| **D. 망분리 환경** | 업무망 시스템과 인터넷망이 분리 | 업무망 시스템에 에이전트 도구를 직접 연결하지 않음. 승인된 망연계 절차로 반출한 **비식별 자료**만 인터넷망에서 분석 | L1~L2 (추천·초안) |
| **E. 완전 폐쇄망** | 외부 전송 불가 | 실데이터로는 사용하지 않음. **가상 데이터로 교육·절차 설계**만 진행하고, 내부 설치형 모델이 필요하면 공급사와 고객사에 별도로 확인 | 실데이터 적용 없음 |

> 유형 C·E의 제공 형태(지역, 설치 방식, 계약 조건)는 바뀔 수 있으니, 제안 시점에 공급사와 클라우드 사업자의 최신 안내로 다시 확인하세요.

## 4. 고객사에 확인할 질문 목록

**보안 지침·승인**
- [ ] 외부 생성형 AI 서비스 사용에 관한 지침이 있는가? 사전 승인 절차는?
- [ ] 허용된 서비스 목록(화이트리스트)이 있는가? 특정 클라우드 사업자만 허용하는가?
- [ ] 업무망에서 외부 API 호출이 가능한가? 프록시·방화벽 예외 신청 절차는?
- [ ] 망연계 솔루션을 통한 자료 반출 절차와 승인자는?

**데이터**
- [ ] 장애 로그·티켓·소스코드·설정 파일 각각의 데이터 등급은?
- [ ] 개인정보가 포함된 자료의 외부 전송이 가능한가? 비식별 처리 기준은?
- [ ] 소스코드를 외부 서비스로 보내는 것이 계약상 허용되는가?
- [ ] 데이터 처리 지역(국내/해외)에 대한 요구가 있는가?

**서비스 조건 (공급사 약관·계약으로 확인)**
- [ ] 전송한 데이터의 보관 기간과 삭제 방식
- [ ] 전송한 데이터가 모델 학습에 쓰이는지 여부
- [ ] 데이터 처리 지역과 재위탁 여부
- [ ] 보안 인증·감사 보고서 제공 여부

**운영·책임**
- [ ] 에이전트의 쓰기 조치(운영 변경) 승인자는 누구인가? (수행사 / 고객사)
- [ ] 감사 로그를 누가, 얼마 동안 보관하는가? 고객사에 제공해야 하는가?
- [ ] 사고 시 보고 절차와 책임 분담은?

## 5. 데이터 반출 판단표 (출발점)

| 데이터 | 기본 판단 | 조건 |
|---|---|---|
| 시스템 로그 (개인정보 없음) | 조건부 가능 | 마스킹 실행 + 필요한 시간대만 |
| 장애 티켓 본문 | 조건부 가능 | 마스킹 + **사람 확인** (이름·주소는 자동으로 안 잡힘) |
| 설정 파일 | 조건부 가능 | 비밀번호·키·인증서 제거 확인 |
| 소스코드 | 고객사 승인 필요 | 계약상 반출 가능 여부 확인 |
| DB 실데이터 (고객 정보) | 원칙적으로 금지 | 스키마·집계 결과만 |
| 인증 정보 (비밀번호, API 키, 인증서) | 금지 | 어떤 경우에도 전송하지 않음 |
| 가상·교육용 데이터 | 가능 | — |

## 6. 마스킹 도구 사용법과 한계

```bash
cd advanced/agent_lab
```
```bash
python3 mask.py samples/ticket_with_pii.txt
```
- 가리는 것: 주민등록번호, 카드번호, 이메일, 휴대전화, 유선전화, 계좌번호, IP 주소, API 키·토큰, 비밀번호 값
- **가리지 못하는 것**: 이름, 주소, 회사·부서명, 사내 시스템 고유명칭. 예시 파일의 "홍길동"은 마스킹 후에도 남습니다.
- 에이전트와 함께 쓰기: `python3 agent.py --pack settle --mask`
  - 목표 문장과 도구 결과를 모델에 보내기 전에 가립니다. 감사 로그에는 원문 없이 건수만 남깁니다.
  - 네트워크 분석처럼 IP가 꼭 필요하면 `--mask-keep IP주소`로 해당 규칙만 뺍니다. 이 경우 IP를 보내도 되는지 고객사 기준을 먼저 확인하세요.
- 규칙은 `mask.py`의 `RULES`에 있습니다. 사업별 고유 형식(사번, 고객번호 등)은 규칙을 추가하고 `test_mask.py`에 테스트를 넣으세요.

> 마스킹은 기본 방어선입니다. **보낼 필요가 없는 데이터는 보내지 않는 것**이 첫째 원칙입니다.

## 7. 요구사항 → 기술 통제 대응표

| 고객사 요구 | 대응 통제 | 위치 |
|---|---|---|
| 개인정보 외부 전송 최소화 | 자동 마스킹 + 사람 확인 | `mask.py`, `--mask` |
| 운영 변경은 승인 후 | 쓰기 도구 승인 게이트 | `harness.py` `Policy.decide()` |
| 모든 행동 추적 | 감사 로그 (원문 대신 마스킹 건수 기록) | `runs/*/audit.jsonl` |
| 최소 권한 | 읽기 전용 계정, 도구 범위 제한 | 계정 발급 · 도구팩 설계 |
| 폭주·비용 통제 | 반복 · 호출 한도 | `--max-iter`, `max_tool_calls` |
| 외부 데이터 속 지시문 대응 | 탐지·표시 + 승인 게이트 | `scan_untrusted()` |

## 9. 교육 운영 시 원칙

- 실습은 **가상 데이터**(`sample-system`, 도구팩 시뮬레이션)로 진행합니다.
- 실제 고객 데이터로 시나리오를 바꾸려면 다음을 모두 거쳐야 합니다. 절차는 `advanced/시나리오_교체가이드.md`에 있습니다.
  - 이 가이드의 판단을 먼저 거친다
  - 마스킹하고, 사람이 결과를 확인한다
  - 고객사 승인을 받는다
- 폐쇄망 고객사의 수강생에게는 기본 과정 데모를 **오프라인 재생**으로, 심화 실습은 **모의 실행**으로 진행합니다. 둘 다 키와 인터넷 없이 동작합니다.
