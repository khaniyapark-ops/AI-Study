# Agentic AI(에이전트형 AI)로 발전하는 과정 — 강의 진행안

**자료**: `에이전트로의_진화.pptx` (20장, 발표자 노트 포함)
**대상**: 전 직무. 관리자·의사결정자 단독 세션으로도 사용 가능
**분량**: 기본 60분 / 확장 90분
**목표**: 수강생이 다음 세 가지를 말할 수 있다.
1. AI가 '알려주는 것'에서 '일하는 것'으로 바뀐 여섯 단계와 각 단계가 더한 능력
2. 규칙 자동화(RPA·스크립트)와 에이전트의 차이, 그리고 둘을 함께 쓰는 법
3. 우리 팀의 AI 성숙도와, 다음 단계로 가기 위해 비어 있는 것

## 어디에 넣나
| 과정 | 위치 | 사용 방식 |
|---|---|---|
| 기본 과정 | ① "왜 Agentic AI인가" 앞 또는 대체 | 오프닝 체험(데모 8 A/B) 직후 20분 축약판: 슬라이드 3, 12, 14, 16 |
| 심화 과정 | 1일차 오프닝 보충 | 성숙도 자가진단(슬라이드 17)으로 트랙 M 과제와 연결 |
| 관리자 세션 | 단독 60~90분 | 전체 진행 + 자가진단 + 투자 우선순위 토론 |

## 60분 진행
| 시간 | 슬라이드 | 내용 | 방식 |
|---|---|---|---|
| 0~5분 | 1~2 | 세 가지 질문 제시. "여러분 팀의 장애 대응은 지금 몇 단계일까요?" 손들기 | 질문 |
| 5~10분 | 3 | 여섯 단계 한 장 요약. 연도보다 '무엇이 새로 가능해졌나'에 집중 | 강의 |
| 10~25분 | 4~9 | 단계별 2분 내외. 각 단계의 "유지보수 현장에서는" 칸을 꼭 읽기 | 강의 |
| 25~30분 | 10~11 | 진화의 동력 5가지, 층 쌓기 그림과 기본 과정 4요소 연결 | 강의 |
| 30~42분 | 12~13 | **활동 1: 같은 장애, 여섯 시대** (아래) | 조별 |

| 47~57분 | 16~18 | **활동 2: 성숙도 자가진단** (아래) | 개인→조 |
| 57~60분 | 19~20 | 정리, 다음 학습 안내 | 강의 |

> 90분 확장: 활동 1을 20분으로 늘리고(재연 + 질의), 활동 2 뒤에 "투자 우선순위 토론" 15분을 추가합니다.

## 활동 1 — 같은 장애, 여섯 시대 (12분)

T-1005 정산 배치 중단(02:10, 연결 풀 고갈)을 각 시대의 방식으로 대응해 봅니다.

1. 6개 조에 단계 ①~⑥을 하나씩 배정합니다. 조가 적으면 ③·⑤만 필수로 배정합니다.
2. 3분 준비: 그 시대에 **누가 무엇을 하는지**, **사람은 몇 시에 무엇을 하고 있는지**, **무엇이 위험한지** 정리합니다.
3. 조별 1분 발표 (슬라이드 12의 표를 띄워 둔 채로)
4. 강사 정리 질문
   - ①에서 자동 재기동이 계속 실패한 이유는? → 원인이 그대로라서. 규칙은 원인을 모른다
   - ③과 ④의 차이는? → 붙여넣은 것만 보느냐, 직접 조회하느냐
   - ⑤에서 사람이 하는 일은 무엇으로 바뀌었나? → 승인·거부와 결과 검토
   - ⑥으로 갈수록 왜 더 어려워지나? → 책임·감사·비용을 조직 단위로 설계해야 해서

## 활동 2 — 성숙도 자가진단 (10분)

1. 개인별로 슬라이드 17의 체크리스트 8개에 표시합니다 (2분).

| # | 질문 | 해당 |
|---|---|---|
| 1 | AI 도구 사용 지침과 마스킹 규칙이 문서로 있다 | ☐ |
| 2 | 팀이 같은 프롬프트 템플릿을 공유한다 | ☐ |
| 3 | AI가 로그·티켓을 직접 조회할 수 있는 도구가 있다 (읽기 전용) | ☐ |
| 4 | 에이전트의 쓰기 조치에 승인자가 정해져 있다 | ☐ |
| 5 | 에이전트 행동이 감사 로그로 남는다 | ☐ |
| 6 | 평가 케이스와 합격선이 있다 | ☐ |
| 7 | 에이전트 1건당 비용을 실측해 관리한다 | ☐ |
| 8 | 사고 시 자율성을 낮추는 기준이 있다 | ☐ |

2. 판정 (제안): 0개 L0 · 1~2개 L1 · 3~4개 L2 · 5~6개 L3 · 7~8개 L4
3. 조별로 결과를 비교하고, **같은 팀인데 답이 다른 항목**을 찾습니다 (5분). 대개 그 항목이 실제로는 "없거나 공유되지 않은" 것입니다.
4. 비어 있는 칸 1개를 골라 슬라이드 18의 "핵심 투자"와 연결합니다 (3분).

> 주의: 성숙도(L0~L4)는 **조직**의 준비 수준이고, 자율성 단계(L1~L4)는 **조치별로 맡기는 범위**입니다. 기호가 비슷하니 수강생이 섞어 쓰지 않도록 짚어 주세요.

## 토론 질문 (선택)
- 우리 팀의 정기 점검 업무 중 ①규칙 자동화가 더 나은 일과 ⑤에이전트가 더 나은 일은 각각 무엇인가?
- 에이전트가 기존 재기동 스크립트를 '도구'로 호출하게 하려면 스크립트에 무엇이 더 필요할까? (예: 사전 조건 확인, 결과 반환 형식)
- ⑥단계로 갈 때 고객사와 가장 먼저 합의해야 할 것은?

## 회상 퀴즈 (5문항)
1. 여섯 단계를 순서대로 말해 보세요.
   → 규칙 자동화 → 머신러닝 예측 → 생성형 AI 챗봇 → 도구 사용·검색 연결 → 에이전트 → 다중 에이전트·표준 연결
2. ③챗봇과 ④도구 사용의 결정적 차이는?
   → 붙여넣은 자료만 보느냐, 도구로 시스템을 직접 조회하느냐
3. ④도구 사용과 ⑤에이전트의 결정적 차이는?
   → 루프: 결과를 보고 스스로 다음 행동을 정하며 목표까지 반복한다
4. 에이전트가 오면 RPA·스크립트는 없어지나?
   → 아니다. 정형 반복은 스크립트가 맡고, 에이전트는 검증된 스크립트를 도구로 호출한다
5. 능력이 커질수록 더 중요해지는 것 세 가지는?
   → 자율성·승인(무엇을 맡기고 언제 멈출지), 평가·감사(제대로 했는지 확인), 책임(RACI·계약)

## 강사 메모
- **연도에 관해**: 슬라이드의 시기는 "현장에 널리 퍼진 무렵"의 대략적 구분입니다. 정확한 연도를 묻는 질문에는 "무엇이 새로 가능해졌는지가 핵심"으로 돌려 주세요. 참고로 확실한 기준점은 세 가지입니다.
  - 트랜스포머 구조 논문: 2017년
  - 대화형 생성 AI 서비스의 대중화: 2022년 말
  - 개방형 연결 표준 MCP 공개: 2024년 말
- **⑥단계에 관해**: 확산 중인 단계입니다. "이미 다 그렇게 한다"고 과장하지 말고, 파일럿 대상의 모습으로 소개하세요.
- **수치에 관해**: 효과 수치(절감률 등)는 넣지 않았습니다. 질문이 나오면 심화 과정의 실측 방식(감사 로그 기반)을 안내합니다.
- **용어**: 표기는 `glossary/사업용어_표준안.md`를 따릅니다. 관련 카드는 챗봇과 에이전트, Agentic AI, 도구, 에이전트 루프, MCP, 자율성 단계입니다.
