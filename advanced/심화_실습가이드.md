> 승인 대기 시간은 장애 복구 시간(MTTR)에 그대로 더해집니다. 승인이 너무 무거우면 아무도 쓰지 않고, 너무 가벼우면 사고가 납니다. 둘 사이의 균형을 정하는 것이 관리자의 일입니다.

### M-4 비용 계산과 파일럿 계획
라이브 실행의 감사 로그에서 `model_turn`의 `input_tokens`, `output_tokens`를 합산합니다.

```
1건 비용(USD) ≈ (입력 토큰 합 × 4 + 출력 토큰 합 × 20) ÷ 1,000,000     # Claude Opus 5.5 표준 단가 기준
월 비용 ≈ 1건 비용 × 월 처리 건수 × (평가·재시도 여유 1.2~1.5)
```
실측 예 (2026-11-20): settle 장애 대응 1건 = 모델 호출 9회, 입력 25,628 · 출력 3,351 토큰 → 약 $0.17. 라이브 평가 9케이스 전체 약 $0.97.
단가는 바뀔 수 있으니 계획서 작성 시점의 공식 가격표로 다시 확인하세요. 1건 비용은 반드시 **실제 라이브 실행 로그**로 계산합니다(모의 실행은 토큰이 0으로 기록됨).

파일럿 계획서 목차
1. 대상 업무와 현재 소요 시간(측정값)
2. 자율성 단계와 승인 RACI
3. 도구 목록(읽기/쓰기)과 사전 조건
4. 평가 기준과 합격선(라이브 N회 중 M회)
5. 위험 관리대장 상위 3개와 통제
6. 비용 추정(실측 1건 비용 기반)
7. 중단 기준(이런 일이 생기면 즉시 L1로 내린다)
8. 고객사 협의 사항

### 심사 평가 기준표 (각 1~5점)
| 항목 | 5점 기준 |
|---|---|
| 문제 정의 | 실제 반복 업무, 현재 소요 시간이 측정되어 있음 |
| 도구 설계 | 읽기/쓰기 분리가 명확하고, 오류 메시지가 다음 행동을 안내함 |
| 가드레일 | 모델이 속아도 지켜지는 규칙이 2개 이상이고, 각각 시나리오로 입증됨 |

| 거버넌스 | 자율성 단계·승인자·중단 기준이 구체적임 |
| 실행 가능성 | 다음 달 바로 L1~L2로 시작할 수 있음 |
