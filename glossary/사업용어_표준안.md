# 유지관리 사업 Agentic AI 용어 표준안

> 버전 1.0 (2026-11-20) · 적용 범위: 유지관리 사업의 교육자료, 월간 보고서, 제안서·계약 부속서, 고객사 안내문, 회의록
> 용어 정의의 원본은 `terms.json`(35개)이고, 카드집·요약표·웹 용어집이 같은 데이터에서 만들어집니다. 이 문서는 **어떻게 표기하고 어떤 표현을 쓰지 않는지**를 정합니다.

## 1. 왜 표준이 필요한가

같은 개념을 사람마다 다르게 부르면, 보고서와 계약서에서 책임 범위가 흐려집니다.
- "AI가 자동 처리했다"는 표현은 누가 승인했는지를 지웁니다.
- "휴먼 인 더 루프", "HITL", "인간 검토"가 섞이면 같은 절차인지 다른 절차인지 알 수 없습니다.

이 표준은 **한 개념에 한 단어**, **책임이 보이는 문장**을 목표로 합니다.

## 2. 표기 원칙

| 원칙 | 내용 | 예 |
|---|---|---|
| 한 개념 한 단어 | 아래 대역표의 '표준 표기'만 씁니다 | "사람 승인"으로 통일 |
| 첫 등장만 영문 병기 | 문서에서 처음 나올 때 `표준 표기(영문)`, 이후 한글만 | 하니스(Harness) → 이후 "하니스" |
| 코드·API 이름은 원문 | 프로그램 속 이름은 번역하지 않고 `고정폭`으로 | `tool_use`, `stop_reason`, `audit.jsonl` |
| 과장 금지 | 자율성은 L1~L4 단계로 표현합니다 | "완전 자동" ✗ → "L4(자동 실행)" ○ |
| 책임이 보이는 문장 | 쓰기 조치에는 승인 주체를 함께 씁니다 | "에이전트가 제안하고 당직 운영자가 승인해 재기동했다" |
| 수치는 근거와 함께 | 효과·비용 수치에는 측정 출처를 씁니다 | "감사 로그 기준 1건 약 $0.17" |

## 4. 혼동하기 쉬운 쌍

| 쌍 | 구분 |
|---|---|
| **사람 승인** vs **승인 게이트** | 사람 승인은 **절차**(누가 무엇을 승인하나), 승인 게이트는 그 절차를 하니스가 강제하는 **지점** |
| **가드레일** vs **하니스** | 가드레일은 막는 장치의 **총칭**(5계층), 하니스는 그중 일부를 구현하는 **프로그램** |
| **반복 한도** vs **재시도** | 반복 한도는 에이전트 루프의 상한, 재시도는 같은 작업을 다시 시도하는 것(예: 배치 retry 3) |
| **평가** vs **테스트** | 평가는 에이전트 행동의 채점, 테스트는 소프트웨어 기능 검증(`pytest`). 평가 안에서 테스트를 쓸 수 있다 |
| **모의 평가** vs **라이브 평가** | 모의 평가는 하니스·가드레일 검증, 라이브 평가는 실제 모델 행동 채점. 모의 통과가 모델 품질을 뜻하지 않는다 |
| **감사 로그** vs **애플리케이션 로그** | 감사 로그는 에이전트의 행동 기록(`audit.jsonl`), 애플리케이션 로그는 시스템 자체의 로그(`app.log`) |

## 5. 권장 표현과 쓰지 말 표현

| 쓰지 말 것 | 이유 | 권장 |
|---|---|---|
| AI가 자동으로 처리했습니다 | 승인 주체가 사라짐 | 에이전트가 원인을 분석해 조치를 제안했고, 당직 운영자가 승인해 실행했습니다 |
| AI가 알아서 조심합니다 | 통제 주체를 오해하게 함 | 쓰기 조치는 승인 게이트에서 사람 승인을 받아야 실행됩니다 |
| 완전 자동화 / 무인 운영 | 자율성 범위가 모호함 | 조회·요약은 L4, 운영 변경은 L3(승인 후 실행)로 운영합니다 |
| AI가 틀릴 리 없습니다 | 환각 위험을 숨김 | 결과는 원본 조회와 평가로 검증합니다 |
| 공수 70% 절감 (근거 없음) | 측정되지 않은 수치 | 파일럿에서 처리 시간을 측정해 보고합니다 (현재 측정 중) |
| HITL 적용 | 약어만으로는 뜻 전달이 안 됨 | 사람 승인(Human-in-the-Loop) 적용 |
| AI가 해킹당했습니다 | 사건 성격이 모호함 | 티켓 본문을 통한 프롬프트 인젝션 시도가 탐지되었고, 승인 게이트에서 차단되었습니다 |

## 6. 문서 유형별 예문

**월간 보고서**
> 11월에는 장애 티켓 1차 분석에 에이전트를 L2(초안)로 적용했습니다. 에이전트가 작성한 원인 분석 초안 12건 중 10건을 담당자가 수정 없이 채택했습니다. 감사 로그 기준으로 무승인 운영 변경은 0건입니다.
> *(수치는 예시입니다. 실제 측정값으로 바꾸세요.)*

**제안서 · 계약 부속서**
> 수행사는 에이전트의 쓰기 조치에 대해 사람 승인(Human-in-the-Loop)을 적용하며, 승인자는 별첨 승인 RACI에 따릅니다. 에이전트의 모든 도구 호출과 승인 기록은 감사 로그로 보관하고, 요청 시 고객사에 제공합니다.

**고객사 장애 안내문**
> 원인 분석은 에이전트가 로그와 설정을 조회해 수행했고, 조치(배치 재기동)는 당사 당직 운영자가 승인 후 실행했습니다. 재발 방지 조치는 고객사 협의 후 진행합니다.

**회의록**
> 결정: 네트워크 포트 재활성 도구에 사전 조건(Rx 광 레벨 기준)을 추가한다. 자율성 단계는 L3을 유지하고, 라이브 평가 합격선(20회 중 19회)을 충족하면 재검토한다.

## 7. 개정 절차

1. 새 용어나 표기 변경 요청은 `terms.json` 수정안과 함께 제출합니다.
2. 교육 담당자와 PM이 검토하고, 승인되면 버전 번호를 올립니다.
3. 아래 명령으로 자료를 다시 생성합니다.
   - 웹 용어집: `python3 build_web.py`
   - 카드집·요약표: `.build_cards.js`. 실행 방법은 같은 폴더의 `README.md`에 있습니다.
4. 이 문서의 대역표와 기존 교육자료(기본·심화 슬라이드)의 표기를 함께 점검합니다.
